1. OBJETIVO PRINCIPAL DEL PROYECTO
--------------------------------------------------------------------------------
Crear un Asistente / Agente Inteligente Local de Terminal que opere con latencia
cero en procesadores CPU, sin depender de la nube, utilizando modelos locales
de Ollama y con capacidades completas de agente autónomo:
- Monitoreo y control del sistema Linux (Ubuntu).
- Ejecución segura de comandos bash en el sistema.
- Cero alucinaciones: verificar siempre la realidad antes de dar cifras.
- Bucle agente autónomo de encadenamiento de comandos en múltiples pasos.

--------------------------------------------------------------------------------
2. PROBLEMAS RESUELTOS DURANTE LA EVOLUCIÓN
--------------------------------------------------------------------------------
A) Eliminación de herramientas pesadas que congelaban la máquina:
   - Se removió Cline CLI: su System Prompt gigante de 8k-32k tokens y modo 'thinking'
     hacían que Ollama tardara hasta 4 minutos en CPU para generar la primera palabra.
   - Se desinstaló Aider y se eliminaron dependencias residuales para mantener
     el sistema limpio y optimizado.

B) Selección y optimización del modelo local:
   - Se descartó phi4-mini como modelo por defecto por su alto consumo de RAM y CPU
     (requería 7 GB y sufría en contexto largo).
   - Se adoptó qwen2.5-coder:1.5b (986 MB): es el modelo más rápido del mundo en su
     categoría para entender comandos Bash y responder en menos de 1 segundo en CPU.
   - Se creó el Modelfile 'enoc-agent' en Ollama limitando num_ctx a 2048 y
     temperature a 0.0 para respuestas ultra-rápidas y deterministas.

C) Erradicación de alucinaciones numéricas:
   - Inicialmente el modelo inventaba porcentajes de RAM cuando se hacían preguntas
     cortas de seguimiento (ej: 'y de ram').
   - Solución: Se programó una regla de oro en el Modelfile y en el script Python
     que prohíbe terminantemente citar números de hardware sin ejecutar antes el
     comando real de Linux (free -h, df -h, ps aux, etc.).

D) Corrección de acciones de control de energía:
   - Al pedirle apagar la PC en 20 segundos, el modelo repetía 'df -h /' por inercia.
   - Solución: Se introdujeron recetas obligatorias de control de energía:
     * Apagado programado: sleep 20 && systemctl poweroff
     * Apagado inmediato: systemctl poweroff || sudo poweroff
     * Reinicio: systemctl reboot || sudo reboot
     * Cancelar apagado: shutdown -c

--------------------------------------------------------------------------------
3. ARQUITECTURA TÉCNICA DEL AGENTE ACTUAL (chat_ollama.py)
--------------------------------------------------------------------------------
A) Bucle Agente Autónomo (Multi-Turn Chaining):
   - El agente no se limita a un único comando por pregunta.
   - Si la consulta requiere varios pasos (ej: 'cómo está mi sistema' o 'cuánto espacio
     y RAM tengo'), el agente ejecuta un comando, lee la salida real de Linux, evalúa
     si necesita más información, ejecuta el siguiente comando, y al final entrega una
     síntesis limpia y comprensible.
   - Soporta hasta MAX_AGENT_STEPS = 6 pasos por turno de usuario.

B) Clasificación Inteligente de Comandos (Seguros vs. Peligrosos):
   - Comandos Seguros (Solo lectura): Se auto-ejecutan de forma transparente para
     agilizar la experiencia (df, free, uptime, ps, sensors, which, cat, ip, etc.).
   - Comandos con Cambios o Peligrosos: Muestran el menú interactivo de aprobación
     con opciones [1-4] y una alerta visual roja (🚨 ATENCIÓN) antes de tocar el sistema
     (rm, mkfs, dd, poweroff, reboot, shutdown, etc.).

C) Interfaz y Usabilidad en Terminal:
   - Historial persistente en ~/.config/antigravity_agente_history con navegación ↑ / ↓.
   - Animación de carga estilo Ollama (braille / spinner) durante el pensamiento y la
     lectura de salidas.
   - Comandos internos disponibles en el chat:
     * /modelos : Lista y permite cambiar de modelo en caliente.
     * /modelo <nombre> : Cambia a un modelo específico de Ollama.
     * /limpiar : Reinicia el contexto de memoria.
     * /ayuda : Muestra los comandos rápidos.
     * salir / exit : Cierra la sesión guardando historial.
